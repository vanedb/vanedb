at five-second intervals, before booting the emulator. The existing diagnostic
screen requires no background process above 50% CPU and aggregate background
CPU no greater than 150%, on the host's `ps` scale. Only the sampler and `ps`
are excluded. No user application was excluded or terminated.

| 21:40:22 | 176.1% | 34.4% | failed |

The initial inspection reported AC, but the retained host inventory and all
six post-build samples report **Battery Power / discharging**, with
`ac_power: false`. A charged battery is not AC power. Thermal output records
no warning, which does not establish an uncontended host. The first three quiet samples did not
predict the subsequent spikes. These are snapshots, not continuous utilization
or isolation proof. The task's request to reserve the host and pause other
work had not received confirmation when this record was prepared; no dedicated
attestation was set for either smoke run.

[Individual host-load samples](evidence/2026-11-01-performance/quiet-preflight.json)

and thermal output. Zero-CPU process rows are omitted in the public copy and
counted; they cannot affect the sums. The complete local record is retained.

but does not override the failed load screen or establish a reserved machine.

### Recording overlay and source boundary

The candidate competitor harness discards individual rounds when constructing
its aggregate report. A [two-line diagnostic overlay](evidence/2026-11-01-performance/raw-round-recording.patch)
emits the already-collected per-engine build, latency and recall arrays as
`RAW_ROUNDS` JSON **after all measured loops finish**. It changes no engine,
workload, parameters, timer, shared-host check, or acceptance threshold.
These competitor binaries therefore identify the candidate plus this explicit
recording overlay, not a byte-for-byte clean candidate harness build.

The patch is retained as evidence and was removed from the candidate worktree
after builds; the binaries and their hashes remain. Reapply it before rebuilding
if individual rounds are required. No such instrumentation was applied to the
Criterion workloads or core engine. The fixed-graph probe is the unchanged
historical diagnostic source, built against each requested revision.
