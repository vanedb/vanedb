published packages, the regenerated filtered-recall figures and one

## Measurement run

One unattended run on an Apple M4 Pro (48 GB, macOS 27.2, AC power), 08:09 to
12:19 UTC, using binaries built from the source commit.

**None of it is dedicated-hardware evidence.** The run applied the same
screen as the earlier campaigns: a 5 s sample fails if any background process
exceeds 50% CPU or the background total exceeds 150%. Flagged samples were
kept, not discarded:

| Phase | Steps | Samples | Flagged |
|---|---:|---:|---:|
| Criterion, `51cb2d8` against RC4, six interleaved passes | 24 | 357 | 66 |
| Criterion, RC2 against RC4, six interleaved passes | 12 | 210 | 4 |
| Competitor harness, cosine | 1 | 388 | 9 |
| Competitor harness, squared L2 | 1 | 417 | 25 |
| Android emulator, cosine (host samples) | 1 | | 85 |
| Android emulator, squared L2 (host samples) | 1 | | 291, plus 14 guest |

The offenders were macOS services (`syspolicyd`, `fseventsd`,
`mediaanalysisd`, `ANECompilerService`, `photolibraryd`), with the Spotlight
daemon suspended for the run. Two earlier runs on the night of 10 to 11
November failed the same screen on other services.

The harness JSON files from this run say `dedicated_attested: true`. That
field reflects an environment variable the campaign script set
unconditionally, not the screen's outcome, and must not be read as an
attestation. The Android files record the commit as `unknown`; the binary was
built from the source commit above.

The numbers below are therefore indicative. No slot in
[bench/COMPARISON.md](../../bench/COMPARISON.md) is filled from them.

### What changed since RC2

RC2 (`8b83c31`) against RC4, medians over three passes each. The four flagged
samples in this phase all fell in distance-kernel steps; every index step ran
with no flagged sample.

| Benchmark | RC4 / RC2 | Every RC4 pass outside the RC2 range |
|---|---:|---|
| `index_search/rs` | 1.009 | no |
| `index_build/rs` | 1.003 | no |
| `index_search/cpp` | 1.086 | yes |
| `index_build/cpp` | 1.004 | yes |
| Distance kernels, 12 rows, both engines | 0.994 to 1.003 | one row, at 0.994 |

The reachability fix (#299) costs the Rust engine about 1% in search on this
benchmark, inside the roughly 3% local noise floor. The same fix ported to
the frozen C++ engine costs it 8.6%. Any Rust-to-C++ search ratio taken after
RC2 is that much more favourable to Rust for a reason that is not a Rust
improvement, and has to say so.

### Competitor harness

100,000 documents and 1,000 queries of 768 dimensions from the pinned
fixture (SHA-256 `4676911521f1…c9c01f2d`), `M=16`, `ef_construction=200`,
`k=10`, seed 42, four rounds. Search time is the median per query at
`ef=50`.

| | Build | Search | Recall@10 |
|---|---:|---:|---:|
| **Mac, cosine** | | | |
| vanedb 0.2.0-rc.4 | 40.8 s | 206 µs | 0.9828 |
| usearch 2.21.0 | 53.6 s | 226 µs | 0.9859 |
| hnswlib 0.8.0 | 97.7 s | 346 µs | 0.9860 |
| **Mac, squared L2** | | | |
| vanedb 0.2.0-rc.4 | 33.2 s | 180 µs | 0.9827 |
| usearch 2.21.0 | 49.7 s | 211 µs | 0.9856 |
| hnswlib 0.8.0 | 98.0 s | 343 µs | 0.9849 |
| **Android API 35 ARM64 emulator, cosine** | | | |
| vanedb 0.2.0-rc.4 | 46.6 s | 236 µs | 0.9828 |
| usearch 2.21.0 | 59.2 s | 262 µs | 0.9856 |
| hnswlib 0.8.0 | 168.3 s | 582 µs | 0.9860 |
| **Android API 35 ARM64 emulator, squared L2** | | | |
| vanedb 0.2.0-rc.4 | 38.0 s | 206 µs | 0.9827 |
| usearch 2.21.0 | 55.2 s | 242 µs | 0.9855 |
| hnswlib 0.8.0 | 107.3 s | 377 µs | 0.9849 |

Two things the speed columns do not show:

- **vanedb returns lower recall at the same `ef`.** At `ef=50` it is 0.2 to
  0.3 points below usearch and hnswlib; at `ef=16` the gap is 0.8 to 1.25
  points against usearch and 0.5 to 0.9 against hnswlib; at `ef=100` it is
  0.1 to 0.25. The engines are not at an equal operating point, and part of
  the search-time lead would be spent closing that gap.
- **The emulator is not a phone.** It runs on the same Mac under
  virtualization. No physical-device result exists.

The harness's peak-RSS column is not reported: it is a process-wide high
water mark that earlier engines in the same process have already raised.

## Maintainer decisions, 2026-11-11

- The search cost measured against RC2 is accepted.
- 0.2.0 may release on the screened-and-flagged data above, with this
  disclosure. The dedicated-hardware slots in
  [bench/COMPARISON.md](../../bench/COMPARISON.md) stay unclaimed.
- The Obsidian plugin built against `@vanedb/wasm@0.2.0-rc.4` was accepted on
  the desktop. It type-checks and builds; 139 of its 140 unit tests pass,
  the exception being its own release gate, which refuses a prerelease
  engine pin by design.
