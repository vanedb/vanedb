# VaneDB 0.2.0 — draft

**Unreleased candidate.** This document accompanies the version metadata bump
from main `487d79b`; it is not a release announcement or sign-off. Rust, Python,
C ABI and WebAssembly package metadata target 0.2.0. The frozen C++ reference
is stamped with the same version for cross-engine identity checks; its Python
package is not published.

## Changes already implemented on the candidate's base

- Per-query allow lists, deny lists and predicates restrict search results in
  Rust, Python, C and WebAssembly. Filtered graph search traverses excluded
  nodes and widens its beam when fewer than `k` results are found, up to the
  configured beam cap. Approximate recall is not guaranteed; tune the initial
  beam and cap against exact search on application data.
- Approximate indexes support byte serialization across bindings. JavaScript
  adds asynchronous `save`/`load` through IndexedDB in browsers or filesystem
  storage in Node; an unknown stored name returns `null`.
- Lookup misses return `Ok(None)` in Rust, `None` in Python and `undefined` in
  JavaScript. Rust callers replace `size()` with `len()` and `get_ef_search()`
  with `ef_search()`. JavaScript callers replace `ef_search` with `efSearch`.
  Python `Metric` is an `IntEnum`. The [changelog](../../CHANGELOG.md) contains
  the binding-specific migrations, including missing-ID removal errors.
- Internal ID hashing and write validation have changed. Dedicated hardware
  performance acceptance is still pending; this draft makes no speed claim.
- The [platform policy](../PLATFORMS.md) records support tiers and floors.
  Metal remains an experimental Rust distance-scan component; it accelerates
  no index. Mobile evidence remains simulator/emulator based.

VNDB v1 disk files, VNDB v2 graph files and legacy readers remain in use.
There is no new persistence format in this version metadata change.

## Dependencies before final release notes and sign-off

The C ABI stage 1 implementation ([#265](https://github.com/vanedb/vanedb/pull/265))
and signed C distribution workflow ([#269](https://github.com/vanedb/vanedb/pull/269))
are separate, still-unmerged candidate dependencies. After integration,
regenerate the C header from the combined sources and add the final integer
handle migration and verified distribution instructions here. Do not describe
those APIs or signed assets as available from this standalone metadata branch.

The remaining milestone/residual work includes dedicated write-path and
competitor results, capacity-study acceptance, the official demo and launch,
and final QA reconciliation. Track [#77](https://github.com/vanedb/vanedb/issues/77),
[#109](https://github.com/vanedb/vanedb/issues/109),
[#210](https://github.com/vanedb/vanedb/issues/210),
[#242](https://github.com/vanedb/vanedb/issues/242) and
[#253](https://github.com/vanedb/vanedb/issues/253) against the accepted RFCs;
closed feature issues do not waive outstanding evidence.

The combined candidate still needs full platform CI, publication-disabled
crate/Python/npm/C rehearsals, installed/extracted artifact verification with
source SHAs and checksums, and independent unanimous role reviews. Record that
fresh evidence before assigning a release date or requesting publication.
