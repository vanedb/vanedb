# VaneDB 0.2.0

Filtered search, WebAssembly persistence, a handle-based C ABI with signed
binaries, and a fix that keeps every stored vector reachable.

```sh
cargo add vanedb
python -m pip install vanedb
npm install @vanedb/wasm
```

Python 3.11 or newer. Wheels cover CPython 3.11 to 3.14 on Linux x86-64 and
ARM64 (glibc and musl), macOS x86-64 and ARM64, and Windows x64.

## New

- **Filtered search** in every binding: allow lists, deny lists and
  predicates per query. Recall is approximate, so tune the beam and its cap
  against exact search on your own data
  ([measured figures](0.2.0-filtered-search-validation.md)).
- **WebAssembly persistence:** asynchronous `save` and `load`, to IndexedDB
  in browsers and the filesystem in Node. Approximate indexes serialize to
  bytes in every binding.
- **Signed C packages** for Linux, macOS and Windows on the GitHub release,
  each with an SBOM and a Sigstore signature
  ([how to verify](../../vanedb-capi/README.md#signed-release-verification-020-onward)).
- **[Platform policy](../PLATFORMS.md)** with support tiers and version
  floors.

## Breaking changes

The [changelog](../../CHANGELOG.md) has the full migration for each binding.

- **Lookups:** a missing id returns `Ok(None)` in Rust, `None` in Python and
  `undefined` in JavaScript, not an error.
- **Rust:** `size()` is now `len()`, and `get_ef_search()` is `ef_search()`.
- **JavaScript:** `ef_search` is now `efSearch`. The old name is silently
  ignored, not rejected, so search your code for it.
- **Python:** `Metric` is an `IntEnum`.
- **C:** handles are `uint64_t`, not pointers. Drop the `*`, use
  `VANEDB_RS_NULL_HANDLE` in place of `NULL`, declare `c_uint64` in `ctypes`,
  and recompile. A 0.1.1 binary run against the 0.2.0 library is not
  refused, and its behaviour is unspecified
  ([C ABI guide](../../vanedb-capi/README.md#using-the-abi)).
- **Graphs:** the same input and seed build a different graph than in 0.1.1.
  File formats are unchanged and existing files still load.

## Fixed

- **Stored vectors that no search returned** (#299). Pruning could cut the
  last edge to a node, under DOT and under cosine on tightly clustered data.
  Every stored vector is now reachable, though a narrow beam can still miss
  one.
- **WebAssembly predicates** that return a Promise or a generator now throw
  `TypeError`. An `async` predicate used to match every id.

## Known limits

- Graphs built with `M < 16` lose some narrow-beam recall to the
  reachability fix: up to 4.5 points at `M = 4`, within 0.6 at the default
  `M = 16`.
- A graph file from an earlier release keeps any vectors that release
  stranded, and nothing reports it on load. `compact()` rebuilds the graph;
  [LIMITS.md](../LIMITS.md#graph-reachability-and-exhaustive-queries) shows
  how to check a file.
- No performance claim is made: no measurement passed the
  dedicated-hardware screen.
- Mobile evidence is simulator and emulator only.
