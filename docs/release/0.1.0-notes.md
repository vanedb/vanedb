# VaneDB 0.1.0

Vector search inside your application, with no database server. Bring your own
embeddings.

```sh
cargo add vanedb                 # Rust
pip install vanedb               # Python
npm install @vanedb/wasm@0.1.1   # Node and browsers
```

[API documentation](https://docs.rs/vanedb) · [changelog](../../CHANGELOG.md)

## What you get

Three index types, all supporting squared L2, cosine and negative dot product,
with `u64` ids and finite fixed-dimension vectors.

| | Exact, in memory | Approximate (HNSW) | Memory-mapped file |
|---|---|---|---|
| Rust | `FlatIndex` | `ApproxIndex` | `DiskIndex` (feature `disk`) |
| Python | yes | yes | yes |
| C ABI | yes | yes | yes |
| WebAssembly | yes | yes | — no filesystem |

Batch insert and delete work on the exact in-memory and approximate indexes.
`ApproxIndex` adds replace and compaction. Rust, Python and the C ABI take a
per-query beam width, so raising recall for one search leaves the index's own
setting alone; in WebAssembly that setting is a property, and replace is not
exposed at all. Optional macOS Metal compute exposes uploaded vectors and distance scans
through Rust; it does not accelerate the indexes themselves.

Platforms: Linux x86-64 and ARM64, macOS Intel and Apple Silicon, Windows x64.
Python wheels cover CPython 3.11–3.14 and add musl Linux; the Rust and C
archives are glibc only. Mobile is verified
on simulators and emulators, including Android ARM64 with 16 KiB pages;
physical-device acceptance is a follow-up.

## Worth knowing before you build on it

- **`DiskIndex::open` is unsafe.** The file must stay unchanged from before the
  open until every mapping is released. A read-only mapping cannot stop another
  process writing to the file, which corrupts results or crashes the process.
  Write updates elsewhere and replace the path atomically. Python and C callers
  carry the same obligation.
- **Approximate search can miss true neighbours.** Tune `ef_search` against
  exact search on your own data.
- **Deleted and replaced graph entries keep their storage** until
  `ApproxIndex::compact()`. Exact indexes reclaim on removal.
- **Building a disk index buffers every vector in memory** before saving.
- **CUDA is not included.** It is the first post-release item on the
  [roadmap](../ROADMAP.md), with no assigned version.

## Formats

`DiskIndex` uses VNDB v1, `ApproxIndex` uses VNDB v2. Both are shared with the
frozen C++ reference engine, which preserves vectors, links, ids and deleted
slots across a load and save — though later insertions may build a different
graph. Legacy readers are retained in each engine; load a legacy file in the
engine that wrote it and save to a new path. Older readers cannot open VNDB v2.

During 0.x, APIs and formats may change in a minor release. Existing format
identifiers are never reinterpreted: a new encoding gets a new identifier, and
readers for existing files are kept.

## npm version

`@vanedb/wasm` starts at **0.1.1**. Its `0.1.0` was consumed during registry
setup and npm never frees a used version. The two lines converge at the next
minor release.
