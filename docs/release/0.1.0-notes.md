# VaneDB 0.1.0 — draft release notes

**Unreleased.** This is the planned first release; package publication and final
candidate verification remain subject to the [readiness requirements](0.1.0-readiness.md).

VaneDB searches embeddings inside your application without a database server.
Supply your own vectors and choose exact in-memory search, an approximate HNSW
graph, or exact search over a read-only memory-mapped file. All three support
squared L2, cosine distance and negative dot product, with unsigned 64-bit IDs
and finite vectors of a fixed dimension.

## Included

- Rust and Python provide Flat, Approx and Disk indexes. Approximate indexes
  support batch insertion, deletion, replacement and compaction. Tune graph
  query `ef_search` against exact search on your own data.
- Rust `SearchParams` selects a query's beam width without changing shared
  defaults. C callers can also select a beam width per query.
- The C ABI provides all three indexes with generated ownership and buffer
  documentation. Native archives include the libraries, header, license and
  runnable CMake examples.
- Node and browser WebAssembly packages provide Flat and Approx indexes,
  batch insertion and deletion. IDs use JavaScript `bigint` values.
- Optional macOS Metal compute exposes explicitly uploaded vectors and distance
  scans through Rust. Enabling it does not automatically accelerate indexes.
  CUDA is a required [follow-up after the initial release](../ROADMAP.md),
  without an assigned version or delivery date.

The candidate targets Linux x86-64/ARM64, macOS Intel/ARM64 and Windows x64;
Python wheels cover CPython 3.11–3.14, including glibc and musl Linux.
WebAssembly targets Node and browsers. Mobile acceptance uses iOS simulators
and Android emulators, including Android ARM64 with 16 KiB pages. The readiness
record distinguishes completed evidence from pending candidate checks.
Physical-device acceptance remains a follow-up.

See the [Rust](../../vanedb/README.md), [Python](../../vanedb-py/README.md),
[C](../../vanedb-capi/README.md) and [JavaScript](../../vanedb-wasm/README.md)
guides for builds and examples. Registry installation commands and release-asset
links will be added after publication is verified.

## Persistence and migration

Disk indexes use shared VNDB v1 files. Approximate indexes write shared VNDB v2
graph files. Rust and the frozen C++ reference preserve vectors, links, IDs and
deleted slots across graph load/save; subsequent insertions can produce different
graphs. Rust retains legacy Rust v1/v2 readers and C++ retains legacy C++ v1/v2/v3
readers. Load legacy files in their original engine and save to a new path.
Older readers cannot open VNDB v2. Keep originals and source vectors while
verifying migration.

During 0.x, APIs and persistence formats may change in minor releases. Existing
format identifiers will not be reinterpreted; new encodings require new
identifiers while retaining readers for existing files. Older readers need not
accept future formats. Identical future insertion topology is not guaranteed.

Rust disk opening is unsafe: keep the underlying file immutable from before
opening until every mapping is released. Python and C consumers have the same
obligation. Read-only mappings cannot prevent another process from modifying
the file, which can corrupt results or crash the application. Write updates to
a separate file and atomically replace the path where supported; existing
mappings retain the original file and new opens read the replacement.

Approximate search can miss true neighbors. Removed or replaced graph entries
retain storage until compaction. Building a disk index buffers vectors in memory
before saving. WebAssembly does not expose persistence, disk mapping, upsert or
compaction. The C++ reference has a different API and feature set.
