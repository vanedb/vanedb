# VaneDB 0.2.0 RC2

Second release candidate for integration testing, not final 0.2.0 acceptance.
Rust, npm and native C assets use `0.2.0-rc.2`; Python normalizes that version
to `0.2.0rc2`. Publication status is recorded on the GitHub release and in
the registry; preparing these notes does not establish published availability.

## Install and test

Use a fresh environment and pin the candidate explicitly:

```sh
cargo add vanedb@0.2.0-rc.2
python -m pip install vanedb==0.2.0rc2
npm install @vanedb/wasm@0.2.0-rc.2
```

Python requires 3.11 or newer. Wheels cover Python 3.11–3.14 on Linux
x86-64/ARM64 (glibc and musl), macOS x86-64/ARM64 and Windows x64; the source
distribution is also included. The npm package serves Node and browser
consumers and is published under `next`, leaving `latest` unchanged.

Native C archives and their signed SBOMs are attached to the
`vanedb-crate-v0.2.0-rc.2` GitHub prerelease for Linux x86-64/ARM64, macOS
x86-64/ARM64 and Windows x64. Verify the complete asset set using its included
`CAPI-VERIFYING.md`, which records the tag identity and exact source commit.
There are no new iOS/Android binary packages or C++ Python publication in
this release.

## Changes since RC1

Every defect found by testing the published RC1 packages is fixed:

- DOT kernels no longer return NaN or disagree across SIMD paths when extreme
  products cancel (#300).
- A graph search whose beam reaches every stored slot falls back to an exact
  bounded scan, so vectors stranded by reverse-link pruning are retrievable
  (#299, query-time remedy; see limitations).
- Python refuses `async def`, generator and deferred-result predicates with
  `TypeError` instead of admitting every candidate (#297, #323).
- WebAssembly accepts safe-integer Number ids, validates vector elements and
  numeric options before coercion, and names the argument it rejects
  (#301, #306).
- The C ABI release publisher reuses an existing draft release (#302).

New in RC2:

- Typed errors: Python `vanedb.VaneError` with one subclass per engine
  failure, each also the built-in it replaced; WebAssembly errors carry a
  `code` mirroring the C status name (#262).
- C ABI `vanedb_rs_index_search_filtered_ex` exposes the filtered-search beam
  cap `max_ef_search`; ABI version stays 1 (#305).
- Documentation states the load-time ABI guard's limit (#303) and the
  selectivity floor of the filtered-search defaults (#304).

See [CHANGELOG.md](../../CHANGELOG.md) for the complete list.

## C ABI migration

Recompile consumers against the candidate header. Store, index and disk
handles are `uint64_t`, not pointers; use `VANEDB_RS_NULL_HANDLE` (0),
`PRIu64`, and `c_uint64` in Python ctypes declarations. Check
`VANEDB_RS_ABI_VERSION` against `vanedb_rs_abi_version()` before other calls.
The guard protects only binaries that call it: a 0.1.1 binary started against
this library is not detected. See the [C ABI guide](../../vanedb-capi/README.md).

Keep mapped disk files immutable until the handle has been freed and all
in-flight calls have returned.

## Known limitations and final-release gates

- HNSW construction can still strand vectors under DOT or tightly clustered
  cosine data (#299). Only a search whose effective beam reaches every stored
  slot is exact; smaller beams remain approximate. See
  [docs/LIMITS.md](../LIMITS.md).
- At low filter selectivity the default beam and cap may return fewer than
  `k` results; raise `ef_search` or `max_ef_search` (#304).
- Dedicated-hardware performance acceptance, Linux AVX2 and Android ARM64
  comparison evidence, and final independent release sign-off remain open.
  This RC makes no performance claim.
- Metal is experimental and accelerates no index; CUDA is not implemented.
  Mobile runtime evidence is limited to simulators/emulators.

Report the RC package version, OS/architecture, installation method and a
minimal reproducer with any issue.
