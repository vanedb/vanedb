# 1.0.0 release readiness

Status: **not ready to tag**. This record tracks evidence and remaining work;
it does not change the release scope or declare support from build checks alone.

## Release scope

Ship the Rust engine, Python package, C ABI and WebAssembly bindings with a
stable public contract, compact maintainable code, runnable user documentation,
and functional verification on every advertised platform. C++ remains frozen
reference code; keep its defect tests and cross-engine fixtures working.

The September 7, 2026 scope decision excludes CUDA from 1.0.0 and makes it a
required, high-priority [roadmap follow-up](../ROADMAP.md). GPU verification for
1.0.0 covers the existing macOS Metal feature. Mobile verification uses
simulators and emulators first; physical-device checks remain a follow-up and carry no success
claim. No later CUDA release version or date has been assigned.

Current integration is based on `1f303a4`, with CUDA removal and review fixes on top.
The earlier green runs below remain evidence for their named revisions; fresh
candidate validation and publication-disabled rehearsals are still required.

Local validation of the follow-up passes: Rust 1.85 checks the whole workspace
with `disk,gpu-metal` (including Python) and the actual wasm32 target; stable
workspace and Metal clippy/tests pass; the cross-engine conformance suite passes;
and a freshly built and installed Python wheel passes all 65 tests, including
concurrent builder and graph snapshot checks. Workflow lint and the all-feature
dependency advisory/license gate pass. The C API beam-width test now has explicit
nonnull ownership; its regression passes, but a fresh CodeQL result is required.
Raw local logs are retained under `/private/tmp/vanedb-release-resume-*.log`.

Independent role review found these release defects:

- Python list batches reserved memory before checking row widths. A tiny
  malformed batch with dimension `sys.maxsize` raised a Rust capacity panic.
  Width validation now precedes a checked-size reservation; the regression
  rejects it with `ValueError` and preserves an empty index.
- JavaScript numeric sizes crossed a Wasm integer boundary before validation,
  silently wrapping or truncating. Constructors, search counts and beam-width
  settings now validate finite, integral, unsigned 32-bit values. Generated
  1.0.0 JavaScript fails the new test before the fix and passes afterward.
- HNSW growth could exceed the file format's 100-million-slot limit and save an
  unreadable graph. A shared guard now rejects add, batch and upsert growth
  before mutation. Lightweight boundary tests prove failed batches and upserts
  preserve the graph without allocating millions of nodes. The format's bytes
  are unchanged; its documentation states the slot limit and RNG evolution policy.
- Node/browser tarballs had identical filenames and lacked checksum sidecars.
  Distributed filenames now include `-nodejs` or `-web`, with SHA-256 sidecars.
  Native archives now record inspected library requirements and the tested host;
  those requirements do not establish oldest-OS runtime support.
- C header-generation errors were silently ignored. They now fail the build.

## Scope and registry decisions — September 7, 2026

The owner accepted CUDA after 1.0.0 and explicitly required it on the roadmap.
The shipping Rust CUDA stub, feature and dependency are being removed from the
1.0.0 candidate. The [roadmap](../ROADMAP.md) requires real NVIDIA hardware and
CI, all-three-metric and edge-case correctness, resource and error handling,
documented CPU fallback, transfer-inclusive performance evidence, and explicit
GPU/toolkit/driver/platform requirements before CUDA support is advertised.
The frozen C++ reference remains unchanged by this scope decision.

Mobile verification proceeds with simulators and emulators for 1.0.0. The owner
reports that Xcode and an iPhone are available, but availability is not runtime
evidence. Physical iPhone and Android acceptance remain follow-up work; no
physical-device pass is claimed. This decision supersedes the earlier
physical-device and CUDA release-gate wording in the historical entries above.

The owner also reports that PyPI was already configured during this release
work. Treat that as user-reported configuration, not a newly verified registry
state; recheck the existing publisher before publication rather than repeating
setup. The Mac is currently locked, which blocks browser verification. A new
crates.io account is still pending; account ownership and bootstrap publication
must be arranged before the crates.io trusted publisher can be used.

Main `19e3927` was incorporated by `91a8478` without changing the integrated
content. Contributor PR #137 (`330b9c4`) and #138 (`0cfe868`) are incorporated in
