Status: **combined candidate integrated; final verification pending**.
Rust, Python, C and WebAssembly use **0.1.1**. PR #184 now includes #185's Wasm

## Candidate and review scope

[Release PR #184](https://github.com/vanedb/vanedb/pull/184) includes main
`65bb39b` through merge `9b53115`, incorporating PRs #185, #186 and #187.
The conflict-resolution audit preserved the constructor-based C++ reducer,
all unnamed-value cases, explicit integer-value and installed-version

This replaces the superseded split-version plan in closed PR #183. The C++
engine remains reference code: its defects are fixed and tested, but its
Python package is not a shipping distribution.

Before final sign-off:

No separate `is_empty` binding is planned: Python uses `len(index)` or truth
testing; WebAssembly uses `index.size()`.

Resolved release findings preserve the first Python batch-conversion error,
make metric hashing/pickle round trips correct, retain wasm runtime/type
validation, and publish the exact tested npm tarball. Onboarding now handles
provider query/document prefixes and states actual API limits. Benchmark
reports no longer attach fixed historical statistics to unrelated workloads.
Version declarations and active release documentation agree. These fixes
change neither the search algorithms nor the persistence formats.

## Platform and compatibility scope

Runtime coverage includes Linux x86-64/ARM64, macOS Intel/ARM64 and Windows
x64. Python wheels additionally cover musl Linux. C archives record glibc
requirements and macOS deployment targets; those are binary requirements,
not proof of runtime behavior on the oldest compatible OS.

Mobile acceptance is simulator/emulator based: iOS ARM64, Android x86-64,
and Android ARM64 with 16 KiB pages. The recorded ARM64 runtime result used
the CI-built binary from `30c1824`. Its native Rust/C implementation, third-party
dependencies and Android build inputs are unchanged at `9b53115`; this supports
carrying forward that runtime result, not claiming a new binary was executed.
Current CI must still pass the mobile builds and acceptance jobs. Physical-device
and oldest-OS runtime acceptance remain follow-ups; no physical iPhone/Android
test is claimed.

Metal is an explicit Rust compute API; it does not automatically accelerate
indexes. CUDA remains a required [post-release follow-up](../ROADMAP.md).
Earlier dedicated-hardware performance evidence applies only to unchanged
implementations; CI timings are not performance evidence. The release delta
keeps third-party dependency versions unchanged.

VNDB v1 disk and VNDB v2 graph formats retain cross-engine conformance and
legacy readers. During 0.x, minor releases may change APIs/formats; existing
format identifiers are never reinterpreted. See the [release notes](0.1.1-notes.md).
