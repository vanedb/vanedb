## Platform and compatibility scope

Runtime coverage includes Linux x86-64/ARM64, macOS Intel/ARM64 and Windows
x64. Python wheels additionally cover musl Linux. C archives record glibc
requirements and macOS deployment targets; these are binary requirements,
not proof of runtime behavior on the oldest compatible OS.

The accepted mobile scope is iOS ARM64 simulator acceptance and Android
x86-64 emulator acceptance, alongside device/ARM64 builds. Android ARM64
16 KiB evidence combines historical emulator acceptance with current binary
alignment checks and source-delta review. The mapping path, dependency
lockfile and alignment configuration remain unchanged; changed validation
and binding behavior requires current tests. Physical-device acceptance is a
follow-up, and no fresh ARM64 runtime result is claimed without a recorded run.

Metal is an explicit Rust compute API and is tested on local Apple hardware.
It does not automatically accelerate indexes. CUDA remains a required
[post-release follow-up](../ROADMAP.md). Earlier dedicated-hardware performance
evidence applies only to unchanged implementations; CI timings are not
performance evidence.

VNDB v1 disk and VNDB v2 graph formats retain cross-engine conformance and
legacy readers. During 0.x, minor releases may change APIs/formats; existing
format identifiers are never reinterpreted. See the [release notes](0.1.1-notes.md).
