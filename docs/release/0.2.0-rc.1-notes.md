# VaneDB 0.2.0 RC1

Release candidate for integration testing, not final 0.2.0 acceptance.
Rust, npm and native C assets use `0.2.0-rc.1`; Python normalizes that version
to `0.2.0rc1`. Publication status is recorded on the GitHub release and in
the registry; preparing these notes does not establish published availability.

## Install and test

Use a fresh environment and pin the candidate explicitly:

```sh
cargo add vanedb@0.2.0-rc.1
python -m pip install vanedb==0.2.0rc1
npm install @vanedb/wasm@0.2.0-rc.1
```

Python requires 3.11 or newer. Wheels cover Python 3.11–3.14 on Linux
x86-64/ARM64 (glibc and musl), macOS x86-64/ARM64 and Windows x64; the source
distribution is also included. The npm package serves Node and browser
consumers and is published under `next`, leaving `latest` unchanged.

Native C archives and their signed SBOMs are attached to the
`vanedb-crate-v0.2.0-rc.1` GitHub prerelease for Linux x86-64/ARM64, macOS
x86-64/ARM64 and Windows x64. Verify the complete asset set using its included
`CAPI-VERIFYING.md`, which records the tag identity and exact source commit.
Archive metadata gives runtime requirements; builds on newer hosts do not
prove support on every older operating system. There are no new iOS/Android
binary packages or C++ Python publication in this release.

## Changes to exercise

- Filtered search across Rust, Python, C and WebAssembly: allow lists, deny
  lists and predicates. Approximate filtered search widens its beam when
  fewer than k results are found; tune recall against exact search on your
  application's data. A full result set does not guarantee exact recall.
- Approximate-index byte serialization across bindings, plus asynchronous
  save/load in JavaScript through IndexedDB or Node filesystem storage.
- Consistent lookup and search vocabulary across bindings. Rust uses `len()`
  and `ef_search()`, JavaScript uses `efSearch`, and Python `Metric` is an
  `IntEnum`. Lookup misses are Rust `Ok(None)`, Python `None` and JavaScript
  `undefined`; removing a missing ID remains an error.
- Shared VNDB v1 disk and VNDB v2 graph formats and retained legacy readers.
  Test reload and migration on copies of existing files.

See [CHANGELOG.md](../../CHANGELOG.md) for the complete migration details.

## C ABI migration

Recompile consumers against the candidate header. Store, index and disk
handles are now `uint64_t`, not pointers; use `VANEDB_RS_NULL_HANDLE` (0),
`PRIu64`, and `c_uint64` in Python ctypes declarations. Check
`VANEDB_RS_ABI_VERSION` against `vanedb_rs_abi_version()` before other calls.
Never-issued, freed or wrong-kind handles report an invalid-handle error.

Keep mapped disk files immutable until the handle has been freed and all
in-flight calls have returned. Freeing the handle does not wait for those
calls. See the [C ABI guide](../../vanedb-capi/README.md#using-the-abi).

## Known limitations and final-release gates

The engine implementation is unchanged from the frozen 0.2.0 source
`fbefa9197960c0398f0dc4762c3cd3ea726d6d6a`; RC version metadata, generated
version strings and packaged installation instructions require fresh artifacts
and validation. The old artifact hashes do not identify RC packages.

- Dedicated Linux AVX2 competitor measurements remain outstanding.
- Android ARM64 emulator measurements completed, but 13/236 host samples
  exceeded the background-load screen. Performance qualification remains
  unresolved. This was a 4 KiB-page emulator, not a physical-device or
  16 KiB-page acceptance run.
- Mac search performance disposition remains unresolved. The full campaign
  alone does not establish a Rust-specific regression; the fixed-graph probe
  showed roughly 4–5% slower searches under a qualified host-load record.
  This RC makes no performance-pass or speedup claim.
- Final independent release sign-off and final 0.2.0 publication remain open.
  RC publication does not waive them. Metal is experimental and accelerates
  no index; CUDA is not implemented. Mobile runtime evidence is limited to
  simulators/emulators; physical-device capacity testing is separate work.

See the [frozen-source evidence](0.2.0-final-evidence.md) and
[Android appendix](0.2.0-android-comparison.md). Report the RC package version,
OS/architecture, installation method and a minimal reproducer with any issue.
