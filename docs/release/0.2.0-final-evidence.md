## Artifact checks

The 60 rehearsal artifacts were downloaded and checked on macOS 27.2 ARM64.
Only macOS ARM64 binaries were executed locally; every other platform rests
on the workflow jobs above.

- **Python:** 28 wheels (CPython 3.11 to 3.14 on seven target rows) and one
  sdist, all `0.2.0`. The macOS ARM64 CPython 3.13 wheel was installed
  without the index into a fresh environment and passed the 298 tests of
  `vanedb-py/tests`, run outside the checkout. The sdist's `PKG-INFO` reads
  `Version: 0.2.0`, `Requires-Python: >=3.11`, and carries no
  release-candidate wording.
- **Core crate:** `vanedb-0.2.0.crate` matches its `SHA256SUMS`; its VCS
  record names S with path `vanedb`; the packaged manifest is `0.2.0` and the
  packaged README carries the unpinned install line. A new crate depending on
  the extracted package built and ran the README quickstart.
- **npm:** `vanedb-wasm-0.2.0.tgz` matches its `SHA256SUMS`, declares
  `@vanedb/wasm` `0.2.0`, and loads under Node through both `require` and
  `import` after installation from the tarball.
- **C packages:** 13 payloads and 13 Sigstore bundles. `capi_release.py
  verify` passed against the rehearsal branch ref and S. These are branch
  signatures; the tag build produces its own and must be verified against
  the tag identity.

## Performance

No dedicated-hardware result exists for this release. One interleaved run on
a developer Mac and an Android emulator failed the load screen; three runs
in all failed it on different macOS services. The numbers, the screen
outcome and their limits are in
[0.2.0-rc.4-evidence.md](0.2.0-rc.4-evidence.md). In summary:

- Against RC2, the reachability fix (#299) costs the Rust engine about 1% in
  graph search, inside the roughly 3% local noise floor, in steps that had
  no flagged sample. Build time and the distance kernels did not move.
- Against the long-standing baseline `51cb2d8`, Rust `store_add` takes 0.57
  times as long, `disk_build` 0.84, `disk_open` 0.94; index build and search
  are flat. In the same run the Rust-to-C++ ratios were 0.80 for `store_add`
  and 1.02 for `disk_build`, both under the 1.1 target of RFC 0010, on a
  host that failed the screen.
- In the competitor harness vanedb built and searched faster than usearch
  and hnswlib on this fixture, at lower recall for the same `ef`.

Maintainer decisions of 2026-11-11: the search cost is accepted, and 0.2.0
may release on this screened-and-flagged data with the disclosure above. The
dedicated-hardware slots in [bench/COMPARISON.md](../../bench/COMPARISON.md)
stay unclaimed, and no performance claim is made in the release notes.

The Linux x86-64 AVX2 tables were deferred past 0.2.0 by the amendment to
[RFC 0003](../rfcs/0003-competitor-benchmark-and-demo.md) accepted on
2026-11-10. No physical Android device was measured.

The September finding of a roughly 5% native search slowdown in a
fixed-graph probe was not reproduced as a separate experiment. The
interleaved runs since then show Rust `index_search` flat against the same
baseline.

## Known limits shipped with 0.2.0

- Graphs built with `M < 16` trade some narrow-beam recall for
  reachability; [docs/LIMITS.md](../LIMITS.md) has the measurements.
- A graph file written by an earlier release keeps its topology, including
  any stranded vectors, until `compact()` rebuilds it.
- Mobile evidence is simulator and emulator only.
