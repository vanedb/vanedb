## Mac measurements and unresolved interpretation

The reserved Mac full campaign completed on 2026-09-27: baseline
`51cb2d871538985aad933a13ebe50c13a0031dfa` versus S, Rust 1.94.1, all 28
Criterion rows in each of six A-B-A-B-A-B passes, followed by four-round
canonical cosine/L2 competitor runs using the pinned 100k×768 fixture and
1,000 queries. Both competitor JSONs pass the unchanged S render-policy gates
and contain the complete expected engine sets. Peer limitations and recall
differences remain in the tables.

Ratios of candidate median Rust to median C++ point estimates are **store_add
0.78×** and **disk_build 1.07×**, both numerically below 1.1×. Both store-add
arms use the same generated IDs and 10,000 128-dimensional vectors (seed 5),
start empty and grow on demand, and exclude construction/destruction from the
timed interval. The input workload is identical, but the API work is not:
`store_add` is the **‡ annotated row** in [the benchmark
notes](../../bench/README.md). Rust resolves an integer handle through a
sharded mutex and an Arc clone/drop on each call; C++ casts a pointer. The
other semantic annotation, **¶**, concerns historical save durability rather
than this row. The old 1.63× figure in #77 belongs to an earlier
source/measurement checkpoint. The ID-map hasher change in #109 is a plausible
contributor to the changed result, but this campaign does not isolate its cost
or establish a causal speedup relative to that historical number.

In the full campaign, Rust index_search rose **3.5%** and the unchanged C++
control rose **2.9%**. The ratio-of-ratios shift is about **0.6%**, inside the
repository's approximate 3% local noise floor; Rust's observed within-arm
interpass spread was about 0.58%. The full campaign alone therefore does **not
establish a Rust-specific search regression**. Control normalization helps
interpret shared drift, but does not prove the source of that drift or replace
the original no-regression acceptance rule.

The unresolved signal is the separate fixed-graph probe: **native Rust +5.0%**
and **C API +4.4%**. Its recorded host-load spikes limit causal
interpretation. Native search slows in that probe too, so added handle lookup
is not established as the cause. The measured C-API-minus-native gap became
smaller, but the paths have different call and memory layouts; their
subtraction does not isolate mutex overhead. The reserved host stayed on AC,
yet process samples recorded substantial background work. Thermal logs
reported no warnings; they do not measure CPU contention. A separate
confirmation completed only its baseline arm before the next quiet-host
preflight failed; that incomplete confirmation is excluded from the complete
ABBA result.

Quick checks found identical baseline/candidate serialized graph bytes and
exact query outputs; standalone finite validation measured about 7.7 ns versus
36 ns for the scalar reference; object sizes changed by 16 bytes. These checks
narrow possible explanations without proving inlined-search timing or an
allocator/layout cause. No functional defect or justified speculative fix was
found. **The roughly 5% native diagnostic observation remains unresolved; Mac
performance is not signed off.**
